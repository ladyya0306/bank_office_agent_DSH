# 办公填表

位置整理需要看来源原文时，使用同一个工具的 `mapping_read: {section: "source"}`。需要完整模板正文时，使用 `mapping_read: {section: "document", template: "工具返回的模板名"}`，按 `next` 续页，不需要另写脚本解压文件。`positions` 和 `mapping_requests` 只列尚未关联的空位，已自动关联的金额、姓名等不会再列出；用 `current_positions` 查看已关联项，不能因未列出就认定漏识别。`mapping_overview` 是整批统计。完成后的 `delivery` 已核验当前产物路径和版本，可直接交付，不需要再数一遍输出目录。

完成响应中的 `execution_summary.generated_files` 和 `reused_files` 分别表示本次调用实际生成和复用的文件数；该摘要不扫描输出目录。

确需核对实际填写文字时，用 `mapping_read: {section: "output", template: "原模板名"}` 读取该模板当前产物，不要自行猜产物路径或编写解压脚本。引擎会按模板已印的人民币单位换算、去掉重复单位和固定后缀；来源字段显示“800万元”不等于实际空位写入了带单位的全部字符，应以实际产物为准。

用户要求填表时，只调用 `office_fill_task` 开始或继续任务。开始时传入当前会话目录内的 `work`、信息源 `source` 和目标模板 `targets`；用户已指定源目录或目标目录时，直接把目录传入对应参数，不要先用 PowerShell 或 glob 列举文件。工具只展开目录中的直接子文件，不递归子目录；用户需要处理子目录时，把子目录本身也作为路径传入。中断后传入 `work` 与 `task_id` 恢复。工具会自行弹出必要问题并继续执行，直接依据终态结果回复。

路径参数可写成 `work: "D:/资料"`、`source: ["source"]`、`targets: ["target"]`；相对路径以 work 为准，Windows 正斜杠可避免反斜杠的 JSON 转义错误。目录输入由工具展开并核验，范围仅含目录的直接子文件；需要读取嵌套目录时，将该子目录本身传入。

通常省略 `batch`，由程序优先恢复同一组源文件和目标文件的已有任务；只有用户明确要求新业务批次才填写 `YYYYMMDD-NN`。不要编造日期、把任务说明当批次，或为了避开错误而换批次、缩减目标文件另开任务。原任务失败不代表已保存的来源答案丢失。

工作区位置以本次网页已确认的办公工作区为准；它可以是任意有读写权限的本地文件夹，不限于 DSH 安装目录。不要沿用其他会话的工作区路径或任务编号。源文件和目标模板放在本次办公工作区内即可，子文件夹名称不限。新工作区由工具自动建立数据库和输出目录，无需用户复制技能、手动建库或先运行初始化命令；同一工作区的新会话先调用该工具查询和继续，已有未变化的确认由工具读取。

遇到程序报错、重复问题编号、数据库异常或“没有推进”，立即报告具体错误与原任务编号，等待修复后恢复；不要立刻重试相同调用，不要在填表任务中检查或修改工具源码、编写排查脚本、重建规则或数据库。仅在用户明确要求修理工具时才开展维护。用户取消或跳过回答时，说明尚未完成；不要立即再问一次。程序修复后继续使用原任务编号，已保存的回答由工具读取。

来源归属与同字段不同值的确认均由 `office_fill_task` 内部弹窗并写库，不要另调普通提问工具收集这类答案。若工具返回失败，不能根据空的 results 就声称“没有任务、没有弹窗、没有保存回答”；只报告返回的失败与已知结果。填表会话的工作区权限不包含共用工具源码，用户提出修复时应交维护环境处理，不能靠普通问题卡上的“同意”宣称文件权限已改变。

同一字段在多张工作表或多个明确空格出现时，共用程序可以保存多个位置；确认卡会列出这些位置，用户回答一次后一起填写。不要再为每个位置另开提问或新任务。程序升级会重查解析和位置，原文、值、归属与位置未变化的旧回答继续复用。

来源、主体和填写位置已经明确且匹配分数足够时，由工具直接填写，不因姓名、金额、账号或日期的字段类别再次逐项确认。只有来源冲突、主体仍有多个合理候选或位置类型不兼容等实际问题才询问。自动填写记录不等于用户作过回答或已签核。

若 `issues` 含 `stage: source`，报告对应来源文件、原文和未处理原因。`partial` 表示仍有未处理内容，即使已经产生文件也不能说全部完成；只说明哪些文件已生成、什么内容还没有处理。不因同一未解析内容连续重试、写修复脚本或改工具源码。复杂叙述的业务含义不能擅自猜填。

仅当结果为 `needs_mapping` 时，才按返回的 `mapping_requests` 逐项处理，并带回该任务的 `task_id`。默认返回一页来源和第一份模板的位置，`mapping_pages.templates.items` 列出模板。来源的 `field` 与 `aliases` 都是可选字段键，同一证据只列一次。若某页的 `next` 不为空，把它原样放进同一工具的 `mapping_read`，并传 `work`、`task_id`；按另一份模板读取用 `mapping_read: {section: "positions", template: "文件名"}`。`details_read` 指向过长证据的完整文字页；完整位置上下文用 `section: "context"`、`template`、`slot_id`。只读分页不会再次解析源或弹出问题，不需要读平台临时文件、解压模板或写脚本抽取来源和位置。

先把全部位置与来源字段对照，完成位置映射后再由工具原生确认值。可以逐页提交已确定映射；剩余页继续原任务。新格式每项使用 `template`、`slot_id` 与 `field`，或使用 `template`、`slot_id`、`leave_blank: true`、`reason`；旧格式 `template`、`field`、`target` 仍可兼容。提交位置和读取页面分开调用，不能同时传 `rule_updates` 和 `mapping_read`。来源或位置变化后旧页版本会失效，重新读取第一页即可。无来源或无签核的信息明确留空。不要把用户回答当成来源值，不要把尚未处理的页面当成已完成；不要改批次、缩减目标或用数据库参数绕过工具。

位置对照要看完整原文、相邻段落、文件用途和来源主体。例如“____同志”应关联该公司的法定代表人姓名；两处“法定住所”不能不看上下文都关联借款人。优先使用已区分借款人、保证人1、保证人2及其法定代表人的来源字段。公司地址和法定代表人证件可以来自不同主体，不要因此宣称资料缺失。授信额度不自动等于本次提款金额；只有业务含义和单位都匹配才关联。普通固定正文中的确认结论不代表用户已经签核。

同一工作簿其他位置已经印好的相同字段，可以作为本模板内的证据。`same_label_references` 给出固定值和位置；核对两处属于同一主体、业务含义一致、没有来源冲突后，可提交 `template + slot_id + template_reference: {sheet, cell}`，不传 `field`。这样无需把模板固定值伪造为来源字段，也不需要用户重新输入。若有多个不同值，必须根据上下文明确选定引用，不能只因标签相同就复制。

`additional_party` 表示模板标出了一个可增减、尚未绑定主体的签约方区块，不表示已经确定该区块的主体。只有来源证据明确关联到当前合同或签约事项，才能把主体填入该区块；不能仅因来源中出现另一家公司或保证人就推定其为本合同签约方。证据不足时保留空白或按任务流程询问；若来源明确要求该主体签署，则据实填写。

分页位置中的 `target_subject` 是根据该填写位置的正文和编号解析出的主体提示；映射时沿用其角色和编号。一个主体区块同时含法人、自然人或证件子栏，不代表可以互换保证人编号；不适用于该主体的子栏可以明确留空并说明原因。

同一批常规填表优先由主代理一次处理；工具已经复用来源和进度，不要仅按文件数量启动多个代理去重复读同一来源和位置页。只有独立且确实复杂的模板需要分工时，才让子代理处理；主代理核查冲突和缺失，不再把子代理读完的模板全部重读。子代理遇到必须由原生交互处理的问题时，应把 `task_id` 和未决问题交回主代理，由主代理恢复同一 task；子代理不要重复尝试提问。提问次数和等待时间按返回的 `interaction_summary` 和 `timing` 统计；`questions` 为空只表示当前无待答，不表示从未提问。无需额外解压或查报告找提问记录。

先看具体填写位置所在的段落、表格和角色编号；正文不能确定主体时，用文件名中的“借款人”“保证人”等说明辅助。普通借款业务材料以当前任务明确的借款人为主，明确的保证人段落采用对应保证人。核保书等多主体文件应按每一栏分别归属，不能以整份文件只准出现一个保证人的假设排除另一个保证人。已确定主体后，其法人、证件、地址沿用来源中的关系，不重复询问同一归属。Excel 左侧标签与右侧金额占位格是一处填写位置，值写入右侧格；分别对照授信金额、已用额度和本次借款金额，不能因数值恰好相同互相代用。

不能为了完成状态而把剩余空位全部留空。有明确来源且含义一致的位置必须提出映射；仅无来源、不适用、用户已要求不填或不能确定的地方留空，并写具体原因。现有模板中的固定文案保持不变，不以参考答案改写正文。程序发现的是可识别空位，不保证所有视觉空白都被识别；结果报告按实际填写和留空说明，不宣称与参考答案完全一致。

交付只按 `delivery.present_calls` 逐项调用 `present`；每项本身就是一个完整参数对象。禁止合并不同项的 `files`，也不要把附件列表平铺后调用。每组最多 8 个附件（报告也计入）。`previous` 是尚待更新的旧结果，`superseded` 是已被新版替代的文件，不能混入当前交付；旧文件保留供追查。`timing` 以秒为单位，用户等待只计原生问题面板实测；标有 `unclassified` 的区间不能拆算为模型或程序耗时，不能拿生成产物的短时间跨度冒充整批耗时。
