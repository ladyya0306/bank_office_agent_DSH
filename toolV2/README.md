# toolV2：固定填表流程

本分支的效率改进候选已实现原工具分页、局部类型检查、确认别名复用、产物版本分组及阶段计时，尚未替换日常运行版本。实际检查、未覆盖范围和回退方法见 [本轮交付记录](../release-docs/填报效率改进候选_20260925.md)。

公开仓库的当前说明以根目录 README 和 release-docs 为准。下文部分历史验证记录只留在维护电脑，未随客户材料或内部记录上传。

这是在原 `tool/office` 基础上做的新版。Word、Excel 的读写代码继续复用；改变的是任务怎样连续往下做。

用户仍可直接说“把这份资料填到这些文件，缺失内容留空，不要替我签核”。不需要背操作口令。

## 一次任务怎么完成

1. 程序检查本工作区已有记录。同一版本的源文件只解析一次。
2. 源材料归属不清时，显示 DSH 原生问题。用户可选建议、暂不收录或自定义回答。
   问题会显示来源文件、完整原文、建议主体和依据。保证人编号、法人关系及明确证件类型由源解析识别；无依据时先提供“暂不收录”，不默认挂给借款人。同一主体的同一字段存在不同值时，工具继续弹出冲突确认题，用户可以选择核实后的值、自定义值或留空，答案仍存入同一个数据库。
3. 已有填写位置继续用。新模板由现有程序寻找位置；无法确定的具体位置返回给模型处理，修复后继续原任务。
4. 要填写的相同内容涉及多份文件时，合成一个问题，并列明涉及的位置。未变化的已确认内容不再问。
5. 回答写入工作区的 `db/workflow.db`。程序直接启动新的 Python 进程，从库取出答案并填写真实文件，不再等模型安排下一步。
6. 每个目标文件分别保存完成结果。再次开始或恢复任务，只处理变化或失败的部分。源文件和目标模板保留原样；新文件在 `out`。

填报完成不代表用户已签核。结果用于用户检查，不替用户签名。

## 本机接入

现在在旁边的 `deepseek-harness-local` 执行 `npm start`，会自动检查 toolV2 接入，并启用新会话的目录选择和工作区确认。配置已经一致时不会重复备份。启动直接使用随包安装的 DSH，不通过 npx 下载。

整理 test2 后可以只留下 `source`、`target`。新会话请选择 `D:\DSH\test2`，办公工作区也确认使用这个目录，不要选到 source 或 target 内。首次填表时程序自动建立数据库和输出目录。删除旧 db 会失去旧确认答案，所以整理后的第一次需要重新确认；后续新会话使用同一个工作区即可读回。聊天历史保存在 DSH 自己的 workspace/sessions 中。

双击本目录中的 `接入DSH.cmd`。它连接旁边的 `deepseek-harness-local`，检查现有 Python 办公依赖，备份原来的接入配置，再启用新版填表工具。它不会联网下载包。

退出并重新打开 DSH，新会话中的填表使用 `office_fill_task`。原生的“允许一次／本会话同类操作一直允许／拒绝”继续由已有批准插件管理。

若当前会话曾反复调用旧命令，建议新开会话，选择原业务工作区。数据库仍在原工作区，不因为新开会话而清空。

接入备份在 `deepseek-harness-local/workspace/backups/office-tool-v2-日期时间`。旧版 `tool/office` 目录没有覆盖。需要回退时，维护人员恢复备份中的 profile、hooks 和技能入口即可；业务数据库的新进度表无需删除。

## 换一台电脑

更换业务工作区不需要重新接入：新建会话，选择本次项目文件夹并确认办公工作区即可。资料与目标模板应在该工作区内，子目录可以任意命名，不必叫 source、target。首次填报会自动建立该工作区自己的数据库；不同工作区的客户资料和确认答案分别保存。同一工作区以后重新开会话，未变化的答案继续复用。

一起复制 `toolV2` 和现有完整的 `deepseek-harness-local`（包括 node_modules），保持两者在同一个父目录下；新电脑需要具备兼容的 Node.js、Python 和办公依赖。执行 `npm start` 会按新电脑的位置更新 toolV2 接入路径，并把原来默认的 deepseek-harness-local/workspace 路径改成本机位置。自定义的其他 workspace 路径仍需自行配置。也可以单独运行 `接入DSH.cmd`。这不代替目标电脑的运行环境验证。

程序不包含新电脑的 Python／Node 安装包。本次在 Windows 本机测试，不能把它说成统信系统已实测；Linux 使用 `python3 install.py --dsh-root <DSH目录>`，运行环境还需在目标机验证。

继续同一项业务时，还应复制整个业务工作区，包括 `db`、`in`、`out`、`work`。仅复制程序不会带走客户资料或用户答案。只要工作区内部结构不变，新版会重新对应本机路径，保留已有结果。

## 这版的实际范围

2026-09-25 后续修复已落到共用程序：一行多个明确标签可以拆分；严格的“本次借款金额为人民币……元”句式产生待确认候选，其他可识别为金额、账号或证件信息的复杂叙述会保留原文并说明未解析。普通说明不逐条要求批准。无冒号的已知表格标签、带格式的 Excel 右侧空格、合并区域、多工作表以及已有 Word 页眉页脚的文字位置已增加支持。同一字段的多个明确位置合并确认后一起填写，不新建数据库。

可重复执行的维护检查为 `python tests/run_material_validation.py`。真实模板副本检查为 `python tests/test_real_layouts.py --templates-dir <模板目录>`，当前该脚本只覆盖记录中的三份特定模板及指定字段，不能将其解释为整份表单所有字段均已验证。详见 `材料适应性修复交付记录_20260925.md`。

- 填写目标为 `.docx`、`.xlsx`，沿用原填写引擎的版式处理能力。
- 源解析以“标签：值”式摘要为主。复杂长篇合同、扫描图片不会因此自动变成通用识别；新增的未解析提示只覆盖明确的业务线索，不能保证发现任何类型的遗漏。
- 新模板不保证自动找到所有位置。修正通过同一工具的 `rule_updates` 传入字段和位置，已有位置发生变化时核对原位置，不按旧编号删除规则。
- 当前任务的源和目标文件需在选定办公工作区内。
- 原始 CLI 是本地维护接口，不是身份认证或操作系统隔离措施。工具程序与 DSH 的权限控制各有职责。

## 维护者看这里

2026-09-25 目标模板修复：新增句中空位、重复位置和合并表格位置清单；`rule_updates` 可用 `template + slot_id + field` 关联来源，或 `template + slot_id + leave_blank: true + reason` 说明留空。先完成位置对照，再原生确认值并填写；未知位置不再依靠临时脚本猜坐标。保留旧格式兼容，位置写入前先验证，不能按旧编号清理规则。详见 `目标模板漏填修复说明_20260925.md`。

| 文件 | 负责的事情 |
| --- | --- |
| `office.py` | 单次 JSON 请求入口 |
| `workflow/runner.py` | 顺序执行、恢复、只处理变化的文件 |
| `workflow/source.py` | 源文件缓存、归属回答及事实入库 |
| `workflow/review.py` | 合并问题、保存和复用目标位置答案 |
| `workflow/storage.py` | 同库保存任务进度；阻止同一工作区同时重复执行 |
| `office_kit` | 从旧工具复用的解析、填写与数据库操作 |
| `dsh-plugin` | 原生弹窗；回答后自动继续；取消时停止本工具的子进程 |
| `install.py` | 本机接入与路径更新 |

旧引擎复制来源见 `engine-origin.json`。不要反复整目录覆盖更新；修具体模块，保留相应行为测试。没有新增 Hermes 等外部依赖。

针对性验证入口：

```text
python -m unittest discover -s tests -p test_workflow.py -v
python tests/acceptance_batch.py
node --test tests/plugin-controller.mjs tests/plugin-process-tree.mjs
```

这些测试使用合成资料，不修改 test2 或其他真实工作区。合成的 15 份文件用于验证工作顺序和复用，不能代替复杂银行模板的逐份验收。
