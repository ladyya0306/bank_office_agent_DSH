# 用一个合成例子读懂记录

下面全是编写的示例，不是真实客户记录。假设来源写着“借款人：示例甲公司”，需要填进两张申请表。

## 先看是否允许程序动手

会话批准查看器会显示类似内容：

```text
#101 询问  工具=office_fill_task  请求号=示例请求1
#102 决定  结果=approved  请求号=示例请求1
```

两条使用相同请求号，说明这次工具操作被允许。它不表示填写内容已确认，也不表示文件已经生成，应继续看工具结果。若选择“本会话同类一直允许”，还有 `approval/policy` 中的 `bankGrant`，包含类别和工作目录；新会话不继承。

原生填写提问与工具操作批准是两回事。“采用建议值”的决定由办公程序保存到数据库，不能只在批准日志里找这个答案。

## 再看资料入库结果

运行 `python scripts/read_office_db.py --work "D:\办公示例\甲公司" --section facts`，可能看到如下结构：

```json
{"id":1,"batch_no":"20260925-01","entity_id":1,"key":"借款人名称","value":"示例甲公司","source_kind":"source","provenance":"来源材料中的借款人段落"}
```

`key` 是什么信息，`value` 是值；`entity_id` 表示属于哪个主体，`batch_no` 是业务批次。`source_kind=source` 表示来自材料，不能把用户新增的内容伪称原文有写。`provenance` 是来源说明，其精确程度以实际记录为准，并不保证每个字都可自动跳转。

## 查看用户确认

把命令中的 `--section facts` 换成 `--section answers`：

```json
{"batch_no":"20260925-01","field":"借款人名称","action":"accept","value":null,"decided_at":"示例时间","run_id":"示例运行编号","fingerprint":"示例确认指纹"}
```

`accept` 表示采用建议值，`value:null` **不是答案丢失**，应结合任务填写计划和来源事实查原建议值。自行填写的新值记为 `new` 并保存文字；留空记为 `blank`；选某主体可能记为 `use`。

确认指纹绑定批次、模板内容、填写位置、建议值及来源等信息。资料或位置变化时不能直接沿用旧同意。源材料归属回答还存于 `office_v2_cache`；任务存于 `office_v2_task`，其 `payload` 是包含来源、目标、状态和逐文件进度的 JSON。

用户在一个填写位置自定义的值，不一定改写原始 `fact`。本版将其保存为该位置的决定，不静默提升为全部业务的永久事实。模板规则保存“哪个字段填哪个位置”，不等于记住某客户的值供下个客户套用。

## 最后看文件结果

把 `--section` 换成 `outputs`。`fill_op` 的 `kind` 分为：`run`（一次执行）、`field`（字段处理）、`artifact`（文件产物）。

```json
{"kind":"artifact","run_id":"示例运行编号","batch_no":"20260925-01","artifact_path":"D:/办公示例/甲公司/out/20260925-01/申请表_已填写.docx","artifact_sha256":"示例文件指纹","opened_ok":1,"status":"ok","signoff_decision":null}
```

`opened_ok=1` 表示程序重新打开过；`status=ok` 表示处理成功；`signoff_decision=null` 表示没有签核决定。不能据“ok”认为用户已经签核。

用 PowerShell 执行 `Get-FileHash -Algorithm SHA256 -LiteralPath "结果文件完整路径"`，与 `artifact_sha256` 比较。相符表示文件与登记时一致，不相符应查修改原因。相符不证明业务含义正确，有权限的人也可能同时改文件和记录。

留空副本目前不一定有常规 `artifact` 行，要同时看任务 JSON 的 `output`、`output_hash` 和报告。

## 一次追溯的实际顺序

结果报告找批次和任务 → `tasks` 找当前输出 → `outputs` 对应执行及文件指纹 → `answers` 看填写决定 → `facts` 对照来源与主体 → DSH 会话查提问、批准和工具结果。绕过办公程序的手动修改需另外说明，现有工具不会自动把所有系统操作补成完整业务日志。
