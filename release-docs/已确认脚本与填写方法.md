# 已确认的方法与任务内来源适配

本文说明任务内临时来源识别脚本如何经过确认后保存和复用。接口已安装到日常DSH，重启后加载；已通过本地自动检查，尚未完成Flash网页独立陌生模板盲测。

## 什么时候使用

普通 `.docx`、`.xlsx`、文本来源先按现有 `office_fill_task` 流程处理。只有来源格式让现有解析器无法可靠识别时，才在当前任务内提出只读识别适配。适配脚本用于读取当前来源、提出字段和值、附上原文位置和文件指纹（SHA-256，用于辨认文件是否改变）。目标位置仍由原有 rule_updates 接口提交；脚本不得直接改共享程序、数据库或原件。

来源解析失败时，仍可用同一任务的 `mapping_read` 读取：

```json
{
  "section": "source_document",
  "source": "in/synthetic-source.docx"
}
```

当前新证据入口支持 DOCX、XLSX、XLSM；文本来源仍沿用原解析流程。返回内容包括原文片段、位置和来源 SHA-256。目标模板也可用 `section: "document"` 只读查看，不因来源解析失败而把模板隐藏。

## 提出方法

通过同一个 `office_fill_task`、同一个 `task_id` 提交：

```json
{
  "learning": {
    "action": "propose",
    "name": "synthetic-document-v1",
    "script_path": ".office-methods/synthetic-document-v1/read.ps1",
    "source_updates": [
      {
        "source": "in/synthetic-source.docx",
        "source_sha256": "<由程序核对的哈希>",
        "rows": [
          {
            "key": "借款人名称",
            "value": "甲方合成公司",
            "evidence": {"paragraph_index": 2},
            "derivation": "原文逐字读取"
          }
        ]
      }
    ],
    "save_target_rules": false
  }
}
```

每个来源更新必须包含登记相对路径、当前文件哈希和 `rows`。每行必须有 `key`、`value`；`entity_name`、`role`、`derivation` 按需要提供。证据位置使用 `{sheet, cell}` 或 `{paragraph_index, part?}`。程序会核对登记路径、哈希和证据正文。值通常必须字面取自原文；如果脚本转换了单位、日期或其他表达，必须填写 `derivation`，并在确认页展示转换过程。用户确认转换只表示允许把该候选纳入本任务，不表示程序已经独立证明业务推理正确。

一个来源文件的更新表示替换该文件本次识别结果；如果只是补充字段，`rows` 仍须带上希望保留的字段，不能只提交新增行而悄悄丢掉旧字段。

## 原生确认与保存

方法学习会进入 `awaiting_method`。所有方法、来源更新和目标规则页面都必须由宿主原生确认完成后才保存。模型消息、脚本中的“已同意”或普通文字回答都不能代替这次确认。

脚本保留为 `.office-methods/<版本>/script.ext` 中的可执行文本；运行仍通过现有 DSH `pwsh` 或其他已批准工具完成。脚本保存和运行分别遵守既有文件写入与命令批准流程。已有批准不会因为方法学习自动扩大范围。worker runtime 只提供工作流运行能力，不应描述为操作系统级安全沙箱。

目标规则只有在任务的映射和确认流程允许时才保存。规则复用依赖同哈希模板；来源识别结果复用依赖同内容、同哈希来源。来源内容变化时，apply 返回 needs_source_update 和重新读取的提示；这不表示脚本失去保存资格。DSH 应重新运行保存的脚本取得新值，再提交确认。模板哈希变化则重新定位，不把旧坐标硬套到新格式。

`list`、`read`、`apply` 用于查询和复用本工作区已确认的方法。查询不会修改文件；`apply` 仍受当前任务、哈希和原生确认约束。

## 完全合成例子

`in/synthetic-source.docx` 内容为：

```text
借款人：甲方合成公司
授信额度：800万元
```

脚本提出两行：`借款人名称=甲方合成公司`、`授信额度=800万元`，并给出各自段落位置和文件 SHA-256。若目标位置要求元，脚本提出 `8,000,000 元`，则必须在 `derivation` 说明“800 万元 × 10,000”，并让用户在方法确认页看到该转换。来源没有“本次提款金额”时，该位置继续留空并说明“来源未提供”；不能拿授信额度代替提款金额。

## 当前边界

本文不扩展到 PDF/OCR，也不代表已经实现按 300 家企业分别输出。未通过目标环境实测的能力仍标为待验收；方法学习成功也不等于填报产物已签核或已发布。


## 在 DSH 里怎样说

可以直接说：“继续当前任务。来源读不懂时，先看原文，不要把零个字段说成零份模板；需要脚本就保存到本工作区。把识别结果和依据交给我确认，确认后保存脚本和填写方法。下次先找已保存方法，来源变了要读取新值，不能复制旧答案。”

保存来源方法与保存模板位置可以分两次做：第一次识别来源后保存，第二次输出核对后再保存目标位置。`save_target_rules` 保存已有位置规则，不包括所有工作区资料，也不把本次填写留空选择当成所有以后任务的固定答案。方法只保存在本工作区；复制到其他电脑时需要另带该工作区的数据库和 `.office-methods`，它们含业务资料，不应加入公共 GitHub 或通用软件安装包。

本轮没有实现“自动查找最合适脚本并无人确认运行”，也没有保证任意 Python/PowerShell 程序都能在其他电脑直接运行。脚本需要的解释器、依赖和工作目录仍须存在。模板换了版式，就由模型重新定位并保存新的确认版本；不是把旧版格子坐标硬套过去。
