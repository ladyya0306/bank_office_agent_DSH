# 在DSH选择百炼Qwen和本地Qwen

2026-09-28已接入百炼Qwen、原有本地1.7B，并新增下载部署本地Qwen3-4B Instruct 2507。保留原有DeepSeek及其默认选择。本次使用DSH已有的多模型接口，没有改toolV2填表逻辑或第三方库。

## 你现在怎么用

### 百炼Qwen

1. 打开`D:\DSH\deepseek-harness-local\.env`，找到已经留好的这一行，将北京地域普通按量API Key填在等号后：

```dotenv
DASHSCOPE_API_KEY=这里换成你的真实API_Key
```

不要再加一条同名配置，不改原有DEEPSEEK_API_KEY。本地Qwen的访问密钥已自动生成，也不用手动改。不要将.env或密钥发到聊天、论坛或GitHub。

2. 保存文件，退出旧DSH，再按原方式启动。已有进程不会自动读取刚填入的环境变量。

```powershell
cd D:\DSH\deepseek-harness-local
npm start
```

3. 在DSH新建测试会话，选择一个合成资料工作区。点输入框右下角的模型名称→“模型”→“阿里云百炼（北京）”下的 **Qwen Plus · 百炼**。只选择模型不会立即发送材料；发送消息后才会调用它。

目前配置：模型ID为`qwen-plus`，接口`https://dashscope.aliyuncs.com/compatible-mode/v1`。使用普通按量API，不是Coding Plan专用接口。131072输入输出合计窗口、8192单次最大输出是本次保守的客户端配置，不是宣称百炼所有型号都具有相同上限。qwen-plus是服务别名，可能随服务更新；做严谨对照时记录响应模型版本，必要时改为双方认可的固定快照。

如果控制台要求工作空间专属地址，可将其填到.env的DASHSCOPE_BASE_URL；要换具体型号，修改DASHSCOPE_MODEL，并让维护者核对容量、工具和思考模式配置。改这两个配置后执行`npm run setup-qwen`，再重启DSH。仅填API Key不用再运行setup。

百炼的地域、Key、已开通模型需一致。本轮没有Key，未实际调用百炼；菜单可选不等于云端鉴权已经验证。[百炼官方接口说明](https://www.alibabacloud.com/help/zh/model-studio/model-calling-in-sub-workspace)

### 本地Qwen3-4B：随DSH启动

模型已经放在`D:\DSH\model`。以后仍然只需运行：

```powershell
cd D:\DSH\deepseek-harness-local
npm start
```

启动器会先加载4B，再打开DSH网页。输入框右下角模型菜单选择 **Qwen3-4B Instruct 2507 Q4_K_M · 本地**。原有会话保留各自模型，安装不会把正在用Flash的会话悄悄切成本地模型。请新建合成资料会话测试，不要假定旧会话已经切换。

不需要再打开一个模型终端，也不需要百炼Key。18082是模型接口，首页404不是聊天网页故障；使用npm start打开的DSH网页（3080）。浏览器没自动打开时，使用启动窗口中的完整网址，不要公开其中的token。

- 模型文件：`D:\DSH\model\Qwen_Qwen3-4B-Instruct-2507-Q4_K_M.gguf`，2,497,280,736字节。
- 原模型为Qwen/Qwen3-4B-Instruct-2507；GGUF由bartowski量化发布，固定版本`ae44f08e1392f39c0e474af10c3ff8355c8b6688`。Q4_K_M表示压缩存储方式，不能理解为与完整精度完全相同。
- 已核对SHA-256：`2fde00ce69dd4899c70d020845e2638353015bba0fdf161b3eb965f2bca4464e`。版本清单保存在model/model-manifest.json。
- 运行程序及DLL在`D:\DSH\model\runtime\b10964`，llama.cpp build10964，commit b29c606e2，Windows x86_64。本机复制自已有程序，4B不再依赖MiniProj的路径。
- CPU 6线程、一次处理1个请求、32768-token总窗口、最多4096-token单次输出。模型只监听127.0.0.1:18082，并使用本地访问密钥。
- 启动器只关闭自己启动的4B服务；发现相同模型已运行则复用，发现端口被其他服务占用则报错，不强杀。4B启动失败时DSH仍可打开使用其他模型，终端会明确说明4B不可用。
- 在启动DSH的终端按Ctrl+C退出时，会释放本次启动的4B。仅关闭浏览器标签页不会退出后台服务。强制结束进程、断电不等同正常退出。

自动加载会占用内存，即使当前选的是云端模型。暂时不用4B时，将.env中`LOCAL_QWEN4_AUTOSTART=1`改成`0`，退出DSH后重新npm start即可；无需删模型或数据库。旧1.7B仍按下一节单独启动。

搬到另一台电脑时，model文件夹需要随离线环境一起带走；GitHub不保存这份2.5GB模型。若仍放D:\DSH，4B路径保持不变；换位置则修改.env中的LOCAL_QWEN4_SERVER和LOCAL_QWEN4_MODEL_PATH。还需要现有DSH、Node、Python及办公依赖，这一文件夹本身不是完整离线安装包。不能整包复制客户资料、会话或云端密钥；新电脑运行setup-qwen生成自己的本地访问密钥。其他电脑的性能和完整断网运行尚未验收。

### 本地Qwen3-1.7B

打开一个PowerShell窗口，执行：

```powershell
cd D:\DSH\deepseek-harness-local
npm run local-qwen
```

等它显示`model loaded`及`listening on http://127.0.0.1:18081`后，保持窗口开启。另一个PowerShell窗口按原方式执行`npm start`启动DSH；若DSH已在运行，不必再启动第二份。

**不要把18081当作聊天网页打开。** 它是DSH调用模型的接口，首页返回404是因为没有启用独立网页。聊天界面在DSH的3080端口；运行`npm start`会打开带本机登录授权的网页。若浏览器没有自动打开，使用DSH启动窗口中输出的完整网址；不要把含token的网址发给别人。只运行local-qwen而没有启动DSH时，聊天网页还没有启动。

在DSH模型菜单里选择 **Qwen3-1.7B Q8_0 · 本地实验**。本地模型服务必须保持运行，菜单不会代你启动它。停止使用时，在本地模型那个PowerShell窗口按Ctrl+C；同一端口不能同时启动两份服务。

这份本地模型不需要百炼Key，也不需要DeepSeek Key；但不要切到旧的云端业务会话继续发送，测试时新建合成资料会话并确认选中的模型。完整应用是否还有其他联网行为，不以本轮模型接口接通替代整机断网验收。

## 已接入的文件与设置

| 位置 | 用途 |
|---|---|
| `.env` | 百炼Key、接口/型号，以及本地模型文件、运行程序、端口、线程数和本地访问密钥 |
| `workspace/settings.yaml` | DSH原生模型配置：新增bailian-qwen、local-qwen和local-qwen4三个提供方，凭据仅引用环境变量名 |
| `setup-qwen.cjs` | 通过已有DSH接口格式注册三个选项；保存设置备份；不修改其他提供方、默认模型或权限 |
| `local-qwen.cjs` | 旧1.7B手动启动与共享参数检查 |
| `local-qwen-autostart.cjs`、`start.js` | 随DSH加载4B，检查模型是否就绪并在正常退出时清理自有进程 |
| `logs/runtime/<本次启动目录>` | 启动及本地模型日志，集中保存 |

## 实际验证与边界

4B部署检查：19项自动检查通过，包括旧1.7B参数、4B路由、加载中503、错误端口、超时和信号退出清理、日志与其他设置保留。真实模型加载约4.9秒；这只是加载时间，不是任务完成耗时。真实DSH退出后18082端口释放，随后实际npm start重新自动加载成功（约4.6秒），原有启动补丁报告无需改动。

4B实际技能测试：使用DSH原生headless命令行入口、新建独立测试设置和会话，仅启用本地模型路由。明确要求加载office-suite技能，模型实际调用1次skill，工具成功返回技能全文，最终正确回答应首先调用office_fill_task。进程正常退出，耗时375.36秒（约6分15秒）。两次推理共18,926 token，其中缓存读取8,148、非缓存输入10,739、输出39；缓存只来自本次测试的前一轮，不是其他业务答案。第一轮8,129输入token，约219.4秒后完成工具调用。

这证明“在DSH里能调用技能、读取工具结果”，不证明它会在任何自然语言任务下主动选对技能，也不证明多步填表、陌生模板或15份材料的正确率。本轮没有执行office_fill_task。网页合成测试在Windows目录选择时因Esc停止电脑操作，随后未继续界面操作，不能写成网页填表验收通过。

本次为CPU 6线程、32768窗口，测试时原1.7B服务仍运行，其他桌面程序也在使用内存；这是当前环境的实际观察，不是排除其他负载的标准速度对比。测试4B时可先在原1.7B启动窗口Ctrl+C，减少同时占用。现阶段将4B作为本地实验选项，不能期待Flash原15份任务的157秒表现。详细合成测试摘要仅保存在本机local-model-smoke-20260928/dsh-test-home/verification-summary.json。
