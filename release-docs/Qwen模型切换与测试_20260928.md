# 在DSH选择百炼Qwen和本地Qwen

2026-09-28已安装两个额外模型选项，保留原有DeepSeek及其默认选择。本次使用DSH已有的多模型接口，没有改toolV2填表逻辑，也没有修改第三方库或下载模型。

## 你现在怎么用

### 百炼Qwen

1. 打开`D:\DSH\deepseek-harness-local\.env`，找到已经留好的这一行，将北京地域普通按量API Key填在等号后：

```dotenv
DASHSCOPE_API_KEY=这里换成你的真实API_Key
```

不要再加一条同名配置，不改原有DEEPSEEK_API_KEY。本地Qwen的访问密钥已自动生成，也不用手动改。不要将.env或密钥发到聊天、论坛或GitHub。

2. 保存文件，退出旧DSH，再按原方式启动。已有进程不会自动读取刚填入的环境变量。

```powershell
cd D:\DSH\deepseek-harness-local
npm start
```

3. 在DSH新建测试会话，选择一个合成资料工作区。点输入框右下角的模型名称→“模型”→“阿里云百炼（北京）”下的 **Qwen Plus · 百炼**。只选择模型不会立即发送材料；发送消息后才会调用它。

目前配置：模型ID为`qwen-plus`，接口`https://dashscope.aliyuncs.com/compatible-mode/v1`。使用普通按量API，不是Coding Plan专用接口。131072输入输出合计窗口、8192单次最大输出是本次保守的客户端配置，不是宣称百炼所有型号都具有相同上限。qwen-plus是服务别名，可能随服务更新；做严谨对照时记录响应模型版本，必要时改为双方认可的固定快照。

如果控制台要求工作空间专属地址，可将其填到.env的DASHSCOPE_BASE_URL；要换具体型号，修改DASHSCOPE_MODEL，并让维护者核对容量、工具和思考模式配置。改这两个配置后执行`npm run setup-qwen`，再重启DSH。仅填API Key不用再运行setup。

百炼的地域、Key、已开通模型需一致。本轮没有Key，未实际调用百炼；菜单可选不等于云端鉴权已经验证。[百炼官方接口说明](https://www.alibabacloud.com/help/zh/model-studio/model-calling-in-sub-workspace)

### 本地Qwen3-1.7B

打开一个PowerShell窗口，执行：

```powershell
cd D:\DSH\deepseek-harness-local
npm run local-qwen
```

等它显示`model loaded`及`listening on http://127.0.0.1:18081`后，保持窗口开启。另一个PowerShell窗口按原方式执行`npm start`启动DSH；若DSH已在运行，不必再启动第二份。

**不要把18081当作聊天网页打开。** 它是DSH调用模型的接口，首页返回404是因为没有启用独立网页。聊天界面在DSH的3080端口；运行`npm start`会打开带本机登录授权的网页。若浏览器没有自动打开，使用DSH启动窗口中输出的完整网址；不要把含token的网址发给别人。只运行local-qwen而没有启动DSH时，聊天网页还没有启动。

在DSH模型菜单里选择 **Qwen3-1.7B Q8_0 · 本地实验**。本地模型服务必须保持运行，菜单不会代你启动它。停止使用时，在本地模型那个PowerShell窗口按Ctrl+C；同一端口不能同时启动两份服务。

这份本地模型不需要百炼Key，也不需要DeepSeek Key；但不要切到旧的云端业务会话继续发送，测试时新建合成资料会话并确认选中的模型。完整应用是否还有其他联网行为，不以本轮模型接口接通替代整机断网验收。

## 已接入的文件与设置

| 位置 | 用途 |
|---|---|
| `.env` | 百炼Key、接口/型号，以及本地模型文件、运行程序、端口、线程数和本地访问密钥 |
| `workspace/settings.yaml` | DSH原生模型配置：新增bailian-qwen和local-qwen两个提供方，凭据仅引用环境变量名 |
| `setup-qwen.cjs` | 通过已有DSH接口格式注册两个选项；保存设置备份；不修改其他提供方、默认模型或权限 |
| `local-qwen.cjs` | 启动本机llama-server，复用现有日志模块 |
| `logs/runtime/<本次启动目录>` | 启动及本地模型日志，集中保存 |

当前使用已有文件：

- 模型：`D:\MiniProj\one-square-meter-civilization-vibe-starter\build\models\resident_planner\Qwen3-1.7B-Q8_0.gguf`，1,834,426,016字节。
- 运行程序：`D:\MiniProj\one-square-meter-civilization-vibe-starter\build\tools\llama.cpp\b10964\llama-server.exe`。
- 本机端口18081，CPU 6线程、1个并发位置、32768-token窗口；关闭思考输出。DSH每次输出上限2048 token，服务自身默认上限4096，DSH请求中的上限优先。
- 仅监听127.0.0.1，并使用自动生成的本地访问密钥；密钥通过子进程环境传递，不写入命令行。配置中的密钥不是云端Key，也不应公开。

模型文件仍在原路径，没有重复复制1.8GB文件。换电脑时需另带获准的模型和对应平台运行程序，并改.env中的LOCAL_QWEN_SERVER与LOCAL_QWEN_MODEL_PATH；这不是已经做好的跨机离线包。更改本地端口或窗口后，重新运行setup并重启模型和DSH，使两边设置一致。

## 实际验证与边界

- 7项自动检查通过：配置保留原Flash默认和其他提供方、重复运行不重复添加、凭据不写入模型设置、生成本地访问密钥且保留其他密钥、无效路径/参数解释失败、启动参数以数组传递。
- DSH原生配置校验接受两条路由；实际网页下拉菜单同时显示原DeepSeek、百炼Qwen和本地Qwen。
- 本地模型实际加载成功；中文短回复成功；普通及流式工具调用正确输出sum_numbers及参数2和3。启用鉴权后，无密钥访问模型列表返回401，有密钥返回200，流式工具调用返回200。
- 百炼缺少Key，尚未完成云端请求验证；未执行15份业务填表，更没有证明1.7B能达到Flash的准确率或157秒速度。
- 本地1.7B先做简单合成资料、少量模板。test B原会话最高单次输入约11.6万token，不能把它原样移到32768窗口；长任务的压缩、工具选择和主体判断能力需要实际对照。

## 撤回本次接入

日常继续选择DeepSeek即可，不运行local-qwen就不占模型内存。若要完全去掉新选项，只移除settings.yaml中llm-pi-ai.providers下的bailian-qwen与local-qwen两项，保留其他设置；不要清数据库或会话。
