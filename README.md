# 银行办公材料整理与填报助手（DSH + toolV2）

把一份来源材料中的信息整理入本地数据库，经用户确认后填写多份 Word、Excel 模板。以 DeepSeek Harness 为交互界面，复用现有文档处理程序，保留工作区、操作批准和过程记录。

**当前状态：个人电脑原型。** 2026-09-26 的主体归属、重复填值、确认复用和格式修复已在本机启用；2026-09-27 安装了集中启动日志。验证范围是15份既有真实模板及合成变体，不代表任意陌生模板、批量300主体、产品合并或OCR流程已验收。最新事实以[维护状态](release-docs/maintenance-state.md)为准。

## 保留了什么

- 新会话先选择会话目录、确认办公工作区；资料、数据库和产物按工作区存放。
- 操作批准可选允许一次、拒绝，或本会话内同类操作一直允许。填报值的确认与工具执行批准是两件事。
- 来源事实、主体、模板规则、填报回答和任务进度使用同一办公数据库。来源、填写位置、批次等未变化时复用已有回答。
- 程序先识别目标位置，再由模型关联来源，使用原生问题卡确认，最后由程序生成新文件。原始来源和模板不被覆盖。
- DSH 会话记录保存交互与批准过程；办公数据库保存经过填报流程的处理记录及部分文件指纹。模型绕流程直接改文件，不能据此宣称数据库已完整记录。

## 仓库范围

本仓库仅包含程序、合成测试、配置生成方法和公开说明。**不含客户文件、数据库、聊天记录、真实 `.env`、凭据以及第三方依赖安装目录。** 因此 GitHub 仓库不是完整的离线安装压缩包。换机需要先准备获准的运行环境和依赖；已有业务的迁移另行按行内要求携带完整业务工作区。

不得因为“本地运行”就声称所有资料不会离开电脑：若使用远程模型，提示词、工具结果可能发送给该服务。办公机不能接模型 API 时，不用代理绕过；应使用获准的本地模型或在获准开发环境验证。

## 开发和回退

验收版本使用独立 Git 标签保存，后续改动在分支或工作树完成，不清理业务目录。维护责任属于当前主代理，不绑定特定模型品牌或代理名称。开发模型测试使用合成资料，不把客户资料提交 Git 或发送给公网模型。

当前代码仍包含原型阶段的兼容处理：启动脚本 `patch-fence.cjs` 会调整 DSH 依赖中的本地网页请求来源检查，仍依赖会话认证，不能对外开放监听后称为安全部署。该行为随验收基线保留，发布前应单独复核。第三方组件信息见 [说明](THIRD_PARTY_NOTICES.md)。
